# Adversarial review ADV6: claude-code-decisions as shipped (main 0cde5c1)

Reviewer: relay row adv-6-decisions, 2026-09-23. I read the code, not the docs: `src/decisions/*`, `scripts/`, `plugin/`, `tests/`, `Makefile`. Every reproduction below was run against a temp repo from `mktemp -d` with the checkout's `src/decisions.py`. I edited no file I reviewed. Recursion first (the D1 to D7 class): the tool starts no process of its own kind, so it cannot fork-storm. Its only children are `git rev-parse` and `pyenv install --list` (ADV6-6). The exposure is wrong greens and live-state coupling.

## Findings

**ADV6-1 (high, wrong green): immutability and "only the owner leaves proposed" are enforced only at the verb.** Anything that edits the file directly (the Edit tool, `sed`) can flip `proposed` to `in-force` and forge `## Words`, and every gate still reads green. Repro: `new` a record, then `sed -i '' 's/^status: proposed/status: in-force/; s/^> (the decider.s words go here)/> forged words/'`. Then `check` prints `# 0 findings over 2 records` with exit 0, `index --check` exits 0, and `scope --governs format` serves the forged record as `in-force`. Nothing compares a record with its committed past. Fix: `check --against <rev>` (the relay gate passes the branch's base sha). A status that differs from `<rev>`, or any byte change to a record that was not `proposed` at `<rev>`, is a finding unless it is the exact front-matter delta that `rule` or `supersede` writes.

**ADV6-2 (medium, invariant bypass): an agent can run `rule`.** The hook's regex `\b(decisions|decisions\.py)\s+rule\b` (`plugin/scripts/deny-rule.sh:12`) needs `rule` to follow the program name directly. The in-tool guard (`writing.py:154`) only tests for `CLAUDECODE`. Repro, hook inputs fed through the script: `decisions --dir . rule 0001 in-force` exits 0 (allowed) and `python3 -m decisions.cli rule ...` exits 0. `env -u CLAUDECODE python3 src/decisions.py --dir $T rule 0001 in-force` from this agent shell printed `0001 proposed -> in-force`, exit 0. Fix: make `rule` require a typed confirmation of the id on a TTY (`sys.stdin.isatty()`), which an agent's Bash does not have. The hook should tokenize with `shlex` and deny any command where a `rule` token appears after a `decisions*` token.

**ADV6-3 (medium, fails open): the deny hook allows the call when its interpreter is slow or missing.** `deny-rule.sh:6` runs `exec python3` from PATH, which is the pyenv shim. D5 measured 60 s waits on pyenv's rehash lock, and the hook's timeout is 10 s (`hooks.json`). A timed-out hook is a non-blocking error, so the call goes through. Repro: `PATH=/nonexistent /bin/sh plugin/scripts/deny-rule.sh < plain.json` gives `exec: python3: not found`, exit 127, which does not block. Malformed stdin also exits 0 by design. Fix: write the match in POSIX `sh` plus `grep -E` (no interpreter), and exit 2 when the input cannot be read.

**ADV6-4 (medium, coupled to live state): the suite reads the caller's environment and the real checkout.** Every CLI-level test calls `decisions.main`, and `main` calls `resolve()` with the real `os.environ` and `HOME` (`cli.py:122`, `settings.py:153`). Repro: `DECISIONS_DIR=elsewhere PYTHONPATH=src python3 -m unittest tests.test_check.CheckThisRepo tests.test_index_render` gives `FAILED (failures=10, errors=2)`, and the same run without the variable is OK. `CLAUDE_CODE_SESSION_ID` is set in every agent shell (it is set here), so a session `resolved.json` with a `decisions` section redirects the suite silently. Separately, `CheckThisRepo` (`test_check.py:266`) and `test_this_repo` (`test_index_render.py:98`) read the real `decisions/` and pin exactly one record, so the second ruling turns `make check` red. Fix: a shared test base that patches `os.environ` to a temp `HOME` and `XDG_STATE_HOME` with no `DECISIONS_DIR` or session id. Delete the two self-checks: `make decisions` already gates the real corpus.

**ADV6-5 (medium, unrun treated as pass): three skips read green.** (a) `tests/gates.py:50`: pyflakes is absent from the `claude-code-decisions` venv (`ModuleNotFoundError`), so the gate prints `skipped` and passes on every run. (b) 38 tests skip without `DECISIONS_LEGACY_REFERENCE` (test_legacy 24, test_convert 9, test_check 3, test_writing 2). After D14 nothing sets that variable, so the legacy path example-app will lean on is not measured by `make check`. (c) `check` prints `readme: skipped` and passes when the source is absent. Fix: a skip exits non-zero unless it is named in a checked-in allow list. Install pyflakes through `make venv`. Pin a small synthetic excerpt of the ledger as a fixture so the legacy tests always run.

**ADV6-6 (medium, hang): `doctor` waits forever on pyenv.** `doctor.py:52` calls `subprocess.run([pyenv, "install", "--list"])` with no timeout. Repro: a fake `pyenv` that sleeps 30 s, then `PATH=$B:/usr/bin:/bin perl -e 'alarm 8; exec @ARGV' $PY -m decisions doctor`. It was killed by the alarm at 8 s (exit 142). `settings.git_top` has no timeout either. Fix: `timeout=10`, with `TimeoutExpired` reported as a `warn`.

**ADV6-7 (medium, wrong green): a ruled record may keep the Decisions and Record placeholders.** `rule` (`writing.py:163`) and `lint_body` (`check.py:163`) test only the Words placeholder. Repro: `rule 0001 in-force` on a fresh `new` whose only edit is the Words line succeeds. `check` then reports 0 findings, and `scope` prints `0001 (1) in-force (the sub-decision goes here) Rejected: (the shape not taken, and why)`. Fix: refuse `DECISIONS_PLACEHOLDER` and `RECORD_PLACEHOLDER` lines past `proposed`, in both places.

**ADV6-8 (medium, concurrency): ids are minted as max+1 with no reservation.** Repro: two concurrent `new` calls in one tree produced `decisions/0001-one.md` and `decisions/0001-two.md`, and `check` flagged `id 0001 duplicates`. Two relay worktrees cut from one main do the same thing without the race window. Each branch's gate is green, and main goes red only after the second merge. Fix: the relay gate measures the branch merged onto the current main, not the branch alone. `new` takes an `O_EXCL` lock under `decisions/` for the same-tree case.

**ADV6-9 (low, partial write): `supersede` and `rule` write two files in sequence with no rollback.** Repro: make the old record read-only, then run `supersede 0001 0002`. It exits 2, but 0002 already carries `supersedes: [0001]` and 0001 has no back link, so `check` reports the one-sided link. Plain `open("w")` can also truncate a record on ENOSPC. Fix: write every file to a temp file first, then `os.replace` all of them. On a failure, restore the files already written.

**ADV6-10 (low, false positive): the hook matches strings, not commands.** The installed hook denied this reviewer's own `for` loop, whose quoted test data contained the phrase. `echo 'decisions rule'` is denied the same way. It is harmless, but it teaches agents to obfuscate. The tokenizing fix in ADV6-2 removes it.

**ADV6-11 (low, public surface): absolute home paths in tracked design files.** `git grep -c /Users/ -- design` finds 8 files (packets and row JSON). The repo is PRIVATE today, so nothing leaks now. The planned public README pass must run hygiene's `home` group over `design/` without an allow row before the visibility changes.

## Verdict

Not ready to carry example-app as the authority for its rulings. The format lints are thorough, and the tool itself cannot fork-storm. But the invariant that makes a record a ruling (the owner alone moves a status, and a ruled record never changes) holds only against an agent that uses the verb politely. ADV6-1 and ADV6-2 together mean an unattended builder can manufacture an `in-force` ruling that every gate accepts. These must be fixed first: ADV6-1, ADV6-2, ADV6-3, ADV6-4 (the suite must be hermetic before relay children run it in parallel), and ADV6-7. ADV6-5 should land with the example-app conversion, since the legacy tests are what measure it. ADV6-6, 8, 9, 10 and 11 can wait for the next hygiene pass. The one fix that matters most is ADV6-1: `check --against <base>` in the relay gate turns every bypass (hook, env or hand edit) into a red.

## The three tests to add first

1. `test_check.Immutable`: commit an `in-force` record in a temp git repo, then flip a `proposed` record to `in-force` by hand and, separately, edit one byte of the ruled record. `check --against HEAD~0` must report both, and a genuine `rule` delta must pass.
2. `test_plugin.HookTokens`: feed the hook `decisions --dir . rule 1 in-force`, `python3 -m decisions.cli rule 1 in-force` and `env -u CLAUDECODE decisions rule 1 in-force`, expecting exit 2 for each. Then feed it `echo "decisions rule"` (expect 0) and an input with no interpreter on PATH (expect 2).
3. `test_hermetic.NoLiveState`: set `DECISIONS_DIR=elsewhere`, `CLAUDE_CODE_SESSION_ID=x` and an `XDG_STATE_HOME` that holds a hostile `resolved.json`, then run the CLI test classes in-process. They must pass unchanged. Add an assertion that no test opens a path under the real checkout's `decisions/`.
